# MeetFlow AI

本地会议工作台。粘贴会议原文后，DeepSeek V4 Pro 生成会议摘要与待办清单，DeepSeek Flash 交叉复核；两阶段均关闭思考模式。每项待办保留原文引句，缺失的负责人或期限显示为「待确认」。

[打开交互 Demo](https://cinderellameixner-spec.github.io/meetflow-ai/) · [查看 20 篇会议的复核模型对照报告](https://github.com/cinderellameixner-spec/meetflow-ai/blob/main/MeetFlow-Review-Comparison.md)

**在线体验。** 打开 Demo，悬停或点按待办标题查看原文，切换会议摘要，确认、略过或勾选行动。演示使用合成会议和预置结果，直接在访客浏览器运行，模型调用次数为零。

**本地使用。** 下载仓库中的 **MeetFlow-AI.zip** 并解压，获得完整工作台、测试和公开评测语料。使用自己的 DeepSeek Key 可以整理新会议。源码中的初稿使用 `deepseek-v4-pro`，复核使用 `deepseek-flash`。在两个复核模型均成功的 17 篇英文会议上，初稿加复核的中位耗时从 8.93 秒降至 6.94 秒；候选待办由用户核对确认。

## 在 Windows 上使用

个人工作目录可以使用 Windows 用户环境变量 `DEEPSEEK_API_KEY`。双击 `start_meetflow.cmd` 后，设置页会提示本机已配置密钥。启用标记位于 `private/local-key-root.txt`，其中只保存本机项目的绝对路径。移动个人项目后，可在新目录的 PowerShell 中执行以下命令重新启用：

```powershell
python -c "from pathlib import Path; p=Path('private/local-key-root.txt'); p.parent.mkdir(exist_ok=True); p.write_text(str(Path.cwd().resolve()), encoding='utf-8')"
```

分享项目时运行 `python build_release.py`，使用生成的 `MeetFlow-AI.zip`。发布包仅包含选定的源码、示例、测试和公开语料。解压后的应用默认只接受访客在页面中填写的 Key，可直接查看预置示例。在线演示使用独立的解压目录，保留这个默认设置。

**要直接填新 Key，双击「填写Key并测试.cmd」。** 在自动打开的密码框粘贴密钥，点击「测试连接」，再点「开始评测」即可处理原有 20 篇会议。英文全文及中文逐字稿评测入口、三版对比、人工评分和复测方法见 [评测说明](benchmark/README.md)。新结果在 `benchmark/runs` 下，早期英文测试目录保留当时的代码快照。

使用 Python 3.11 或更高版本。双击 `start_meetflow.cmd`，浏览器会打开 http://127.0.0.1:7860 。保持启动窗口打开，按 Ctrl+C 结束服务。也可在项目文件夹中运行：

```powershell
python app.py --open
```

打开后显示一份**预置的合成产品周会**。替换左侧文本，填写开会日期，点击「整理会议」会将本次会议发给 DeepSeek。可以在「模型设置」输入 API Key，也可使用本机的 `DEEPSEEK_API_KEY`。页面输入的 Key 刷新后清空。

### 保存会议与跟进待办

1. 在 MeetFlow 工作台查看摘要与待办。鼠标停在待办标题上、用键盘聚焦标题或直接点按，左侧原文会高亮对应引句。跨会议清单中点标题可打开来源会议并定位。点「修订待办」可更改行动、负责人、期限和提醒时间；修改后的标题仍指向原始引文。
2. 点击「保存会议」后，原文、摘要、原始提取及人工修订写入本项目的 `private/workspace.sqlite3`。相同日期和原文重复保存会打开已有会议。预置示例也仅在主动保存后进入历史。「历史会议」按日期排列，可搜索标题和原文。
3. 在「我的待办 → 我的姓名与别名」中填写自己在会议中的称呼。「我负责的」按姓名匹配，「待认领」可认领暂无负责人的行动，「全部待办」可跨会查看。每项均可打开来源会议。勾选即记录完成时间并显示删除线，再点可撤销。
4. 明天、下周一、具体月日等按开会日期换算；不明确的期限进入「无明确日期」。个人未办结任务默认在截止日当地时间 09:00 提醒，可指定时间或关闭。打开或返回页面时会补显到时提醒，当前可见页面约每 15 秒更新。「知道了」确认本次提醒，改期后按新日程提醒。已办结任务停止提醒。

工作台供单机个人使用。复制项目到新位置时，一并保留 `private/workspace.sqlite3` 即可带走历史记录。

摘要或待办通过初次校验后即可阅读；交叉核对结束后可保存整场会议，遗漏候选可逐条确认。页面分别显示首项和完整结果的耗时。相同原文在模型和分析规则一致时可复用完整核对结果。服务在内存保留最近 32 份结果，保存会议时也保存可复用的原始分析。点「重新整理」可重新调用模型，历史记录保留已有的人工修订。

### Gradio 界面

在项目目录的 PowerShell 运行以下命令。依赖装在项目环境中：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py --open
```

检测到 Gradio 时，应用以 Gradio Blocks 挂载到 FastAPI。未安装时自动使用 Python 标准库提供同一界面和模型处理流程。端口被占用时可以运行 `python app.py --port 7861 --open`。

## 处理方式

- 会议摘要包含主题、概述、已确认结论和重要未决问题。待办包含行动、负责人、期限、逐字引文。
- 短文本并行请求两个子任务。超过 5,500 字符时采用带重叠的分段提取，然后汇总摘要、结合全文复核任务，处理改期、撤销和跨段重复。单次输入上限 80,000 字符。
- 模型输出使用 JSON 模式，校验字段类型和引文是否在原文中。可解析 Markdown 代码围栏。空结果、无效 JSON、结构错误或可恢复的网络错误最多重试两次。鉴权失败、余额不足会直接提示。
- 提取策略可复现。v1 强调 JSON 和任务拆分，v2 增加待办定义及正反例，v3 识别无主语任务并分段处理长文本。实际质量差异需用相同会议逐版测量。

## 评测真实会议

在 `private/meetings.jsonl` 中每行放一条脱敏会议。每条先由人工列出独立待办，每个动作占一项。以下为格式示例：

```json
{"id":"M01","text":"周五前把预算表整理出来。培训材料已经发过了。","gold_tasks":["周五前整理预算表"]}
```

1. 准备 20 条有使用权限的真实会议。另留开发样本用于迭代 Prompt。三版对比时保持会议、标注和评分规则一致。
2. 在已配置 `DEEPSEEK_API_KEY` 的终端运行 `python evaluate.py run private/meetings.jsonl private/v3.jsonl --version v3`。程序向 DeepSeek 提交会议并逐条保存结果。输出必须使用新文件名，以保留之前的人工评分。比较 v1/v2 时更换版本参数和文件名。
3. 打开结果文件，给每条成功样本填写 `matches`。例如 `[[2,1]]` 表示模型第 2 项与人工第 1 项对应，编号从 1 开始。一条预测最多对应一条人工标注。动作和对象一致且已明确的负责人、期限没有实质冲突时可匹配。完全不匹配填 `[]`。
4. 给每条成功样本的 `ratings` 四项填 1–5 分。1 分代表存在严重问题，3 分基本可用但需纠正，5 分可直接使用。coverage 看重要结论、争议及后续行动的覆盖，fidelity 看人物、数字、日期和决策状态的一致性，conciseness 看重复与无关细节，readability 看未参会者能否读懂。权重依次为 30%、30%、30%、10%。
5. 运行 `python evaluate.py score private/v3.jsonl`。精确率、召回率按全部会议的 TP/FP/FN 汇总。一场失败的会议也进入分母，该场人工待办全部算漏提。格式通过率是最终得到合规可用结果的会议数除以总会议数，包含重试。摘要均分只统计有可用结果的会议，同时报告数量。
6. 批处理耗时从程序提交到最终可用结果，含模型、重试与合并。输出成功会议的中位数、P95 和最大耗时，并单独判断是否每条会议均成功且低于 3 秒。页面展示的耗时还包含浏览器与本地服务之间的往返。

85% 召回率、4.2/5 摘要评分、接近 100% 的格式通过率和单条小于 3 秒目标均已验证。预置示例和模拟响应测试不参与真实模型评测。

## 本地检查

```powershell
python -m unittest discover -s tests -v
```

`app.py` 提供本地服务，`meetflow.py` 包含 Prompt、模型请求、校验及分段合并，`evaluate.py` 负责真实样本评测。请将真实样本、生成结果和人工评分放在已忽略的 `private/` 目录。
